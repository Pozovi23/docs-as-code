### US-01. Проверка письма на спам

Как получатель письма,
я хочу, чтобы входящее письмо автоматически проверялось на спам,
чтобы не тратить время на нежелательные сообщения.

Критерии приёмки:

- система принимает входящее письмо (текст и/или отправителя);
- после обработки отображается результат: "спам" или "не спам";
- если проверка невозможна, пользователь получает сообщение об ошибке.

### US-02. Пометка письма как спама

Как получатель письма,
я хочу, чтобы письма, определённые как спам, автоматически помечались,
чтобы сразу видеть, какие сообщения можно не открывать.

Критерии приёмки:

- письмо, классифицированное как спам, получает метку "спам";
- письма, определённые как "не спам", остаются без метки;
- метку можно снять вручную.

### US-03. Ручная корректировка метки

Как получатель письма,
я хочу иметь возможность вручную снимать или ставить метку "спам",
чтобы исправлять ошибки модели и не терять важные письма.

Критерии приёмки:

- у каждого письма есть кнопка/действие для смены статуса ("спам" / "не спам");
- если пользователь снимает метку "спам", письмо возвращается в обычную папку "Входящие";
- если пользователь помечает письмо как спам вручную, система сохраняет это действие (например, для дальнейшего дообучения модели).

### UC-01. Проверка письма на спам

Актор: получатель письма.

Цель: определить, является ли входящее письмо спамом.

Предусловие: письмо поступило в почтовый ящик получателя.

Основной сценарий:

1. Система получает входящее письмо.
2. Система извлекает текст и данные отправителя.
3. Система передаёт данные ML-модели.
4. ML-модель определяет класс письма ("спам" или "не спам").
5. Система получает результат классификации.
6. Получатель видит результат проверки для письма.

Альтернативный сценарий:

Если модель не может обработать письмо (например, пустой текст или неподдерживаемый формат), система сообщает, что письмо требует ручной проверки, и не ставит метку.

Результат: письмо классифицировано и при необходимости помечено как спам, либо передано на ручную проверку.
